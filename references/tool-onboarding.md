# 工具与项目上手

用于 GitHub 项目、产品网站、桌面应用、浏览器插件、AI Skill 等入门。

## 先识别，再安装

遵循主文件的开场顺序：先请用户说打算怎样使用，已表达则直接据此判断。下面的资料分析可在后台做；不要在用户说出想法前，先把整套用途和操作流程教完。

阅读官方介绍和用户入口，分清成品软件、在线服务、源码库、开发者组件、插件或 Skill。仓库里的“开发环境安装”可能面向贡献者，不是普通用户的使用入口。

回答四件事：能做什么；谁适合用；用户从哪里操作；今天怎样得到第一个结果。不复述整篇 README，不先讲目录结构或代码架构。

优先选择官方支持、适合当前环境的简单路径，例如已有在线入口或安装包；用户指定产品时保留其选择。项目仅提供源码、需要付费服务、硬件不足或不支持当前系统时，解释具体缺口。提供可行选择并让用户决定是否换方案，不悄悄换产品。

当前版本、系统支持、价格、下载链接、安装步骤从官方资料核实，注明不能确认的部分。必要时看发行说明、配置示例或源码入口；不要克隆整个仓库作为固定前置步骤。明确区分官方写明的能力和已经在本机验证的能力。

## 建立可用链路

### 缺少执行任务的 AI 助手时

“再找一个支持的客户端”不是一个新手可以直接执行的步骤。先说明缺的功能以及是否必须补上，优先检查用户已装的软件。用户坚持使用指定工具时，不把普通聊天体验冒充该工具使用成功。

确需新软件且可以查资料时，核实一个适合其系统的候选：官方入口、账号与费用条件、必需的本地操作能力、目标工具当前接入方法。给一个推荐理由和必要条件，不先倒出软件排行榜；若涉及新增费用、注册或更换软件，讲清之后由用户选择。用户已选定并授权的路线直接推进。

按“取得安装包 → 安装 → 打开 → 必要设置 → 在实际会话中检查能力”带做，不把官方兼容列表当作本机已连通。相关步骤按用户状态跳过。到新的聊天窗口时按 [handoffs.md](handoffs.md) 交接。

不能核实可用候选或接入方法时，指出具体缺失资料和恢复条件。用户可以提供产品名、官方说明、界面或自检回复；已经明确拒绝新增软件时停止反复追问，交付进度和可选替代体验。阻塞状态要保留，不能用假定环境填平。

### 已有可行路径时

1. 确定用户的第一个目标以及手头已有的环境。
2. 只补上这个目标缺少的依赖，确认已安装的软件后再考虑安装。
3. 按当前官方路径完成必要设置。每轮一个用户动作；AI 能处理且已授权的部分直接处理。
4. 验证目标客户端实际能调用该能力；“已安装”和“当前会话能用”分开确认。
5. 回到用户目标，完成一个最小任务并检查结果。
6. 留下再次使用的入口和指令。

无法继续时定位：下载/安装 → 启动 → 账号 → 客户端识别 → 连接 → 任务本身。不把每一种错误都归因于“没装好”。

用户说安装完成但证据不明时，可以问“现在看到的是下载完成提示，还是已经打开的软件窗口？”获得实际状态后继续，不让已经真正完成安装的人重做整套流程。

## 用户不会安装本教学 Skill

先识别用户使用的 AI 客户端，以及是否支持 Skill、文件附件或读取本地文件。安装位置和发现方式以该客户端当前官方说明为准，不把某台机器的绝对路径给所有用户。

支持 Skill 时安装本目录，并按需开启新会话检查是否识别；不支持时可把本 SKILL.md 与当前分支参考文件作为附件或文本提供给 AI，称作“教学提示词使用方式”，不宣称已经安装或获得文件/浏览器控制能力。没有读取文件能力时，使用配套启动说明中的简版提示词。
